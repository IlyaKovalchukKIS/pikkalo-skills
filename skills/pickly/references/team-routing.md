# Команда: Claude Code + Codex

Подписки: **Claude Pro** (лимиты меньше) и **ChatGPT Pro** (Codex, лимиты большие).
Отсюда правило: Claude — «голова и вкус», Codex — «руки». Объёмный код пишет Codex,
Claude тратит токены там, где важны суждение, дизайн и слова.

## Маршрутизация по типу задачи
| Тип задачи | Исполнитель | Ревьюер |
|---|---|---|
| Новый экран, анимации, UX-поток | Claude: спецификация + ключевые компоненты; Codex: рутина вокруг | Claude (дизайн + тексты) |
| Тексты, онбординг, пейволл, пуши | Claude | — |
| Разбор отзывов (triage) | Claude (Sonnet, коротко) | владелец в Telegram |
| Баг с понятной причиной, рефакторинг, тесты | Codex | Claude только если UI |
| Бэкенд Yandex Cloud (функции, YDB), CI | Codex | Codex (self-review) |
| Нативный модуль `pickly-vision`, алгоритмы фото | Codex реализует, Claude ставит задачу и проверяет логику | Claude |
| Миграции зависимостей, массовые правки | Codex | — |
| Непонятный баг, нужна диагностика | Codex (дешевле перебор) → если не нашёл, Claude | — |

Правило по умолчанию: если задача описывается одним абзацем и не трогает внешний вид — Codex.

## Экономия токенов
1. **Одна правда в файлах, а не в чате.** Решения — в `docs/DECISIONS.md`, задачи — в
   `tasks/TASK-NNN.md`. Агенты читают файл, а не пересказывают историю.
2. **Короткие инструкции верхнего уровня.** `AGENTS.md` и `CLAUDE.md` ≤ 100 строк, детали —
   в справочниках скилла, которые читаются только по необходимости.
3. **Передача работы — через задачу-файл** (шаблон ниже): цель, файлы, критерии готовности.
   Исполнитель не исследует проект заново.
4. **Узкий контекст.** Указывай конкретные файлы и строки; не проси «посмотри весь проект».
5. **Дешёвая модель для простого.** Triage, переименования, тексты — Sonnet/Haiku
   (`--model sonnet`); Opus — только архитектура и сложный UI.
6. **Ревью диффа, а не репозитория.** Ревьюер получает `git diff main...HEAD`, а не дерево.
7. **Не дублировать работу.** Один исполнитель на задачу; второй агент — только ревью.
8. **Кэшируемые префиксы.** Стабильные инструкции в начале промптов, изменяемое — в конце.
9. **Новая сессия на новую задачу.** Длинные сессии дороже: каждое сообщение тянет историю.

## Шаблон задачи `tasks/TASK-NNN.md`
```markdown
# TASK-NNN: <коротко>
Исполнитель: codex | claude      Ревьюер: claude | —      Источник: issue #N | владелец
## Цель
<1–3 предложения: что должно стать правдой для пользователя>
## Контекст
- Файлы: src/…/Foo.tsx:40-120, src/…/bar.ts
- Решения: DECISIONS.md#… (если есть)
## Сделать
1. …
## Не делать
- …
## Готово, когда
- [ ] …
- [ ] тесты: `npm test -- foo`
- [ ] инварианты Pickly соблюдены (.agents/skills/pickly/SKILL.md)
```

## Локальный запуск Codex
- `codex exec --sandbox workspace-write -c sandbox_workspace_write.network_access=true "…"`
  из корня репозитория, на отдельной ветке; сеть нужна для npm.
- В этом режиме `.git` для Codex только для чтения — **коммиты делает Claude после ревью**.
  Codex пишет предлагаемые сообщения коммитов в «Заметки» задачи.
- Длинные задачи запускать в фоне, лог — во временную папку; не опрашивать.

## Процесс
1. Задача появилась (отзыв, идея владельца, баг) → маршрут по таблице.
2. Если задача на UI — Claude пишет спецификацию экрана (состояния, движение, тексты) в
   задачу-файл; Codex реализует по ней.
3. Исполнитель открывает PR с `Closes #N` и ссылкой на TASK.
4. Ревью по режиму `review` скилла → правки → владелец вливает.
5. Решения, принятые по ходу, — одна строка в `docs/DECISIONS.md` (дата, что, почему).
