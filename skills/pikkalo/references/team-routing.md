# Команда: Claude Code + Codex

Подписки: **Claude Pro** (лимиты меньше) и **ChatGPT Pro** (Codex, лимиты большие).
Отсюда правило: Claude — «голова и вкус», Codex — «руки». Объёмный код пишет Codex,
Claude тратит токены там, где важны суждение, дизайн и слова.

## Обязательное делегирование (правило владельца)
**Если Codex подключён и у него есть лимиты — реализацию делает Codex. Всегда.** Это не
рекомендация: Claude, который сам пишет код или объёмный текст при живом Codex, нарушает правило.

**Проверка перед любой задачей с правкой файлов:**
`.agents/skills/pikkalo/scripts/codex-delegate.sh check` (в репозитории скилла —
`skills/pikkalo/scripts/…`). Код 0 — Codex подключён → делегируй.

**Что делает Claude:** уточняет задачу у владельца, пишет `tasks/TASK-NNN.md`, создаёт
worktree, запускает Codex, проверяет дифф и результат (тесты, эмулятор), правит мелочи после
ревью, коммитит, открывает PR и вливает. Плюс то, что требует вкуса и слов: UI-спецификация,
тексты, triage, ревью.

**Что делает Codex:** всё остальное — код, тесты, нативные модули, алгоритмы, миграции,
скрипты, объёмные справочники и документация по готовому плану.

**Запуск:**
```bash
git worktree add -b feat/task-NNN ../pikkalo-task-NNN origin/main
ln -s "$PWD/node_modules" ../pikkalo-task-NNN/node_modules   # для JS-проектов
cp tasks/TASK-NNN.md ../pikkalo-task-NNN/tasks/
.agents/skills/pikkalo/scripts/codex-delegate.sh run tasks/TASK-NNN.md ../pikkalo-task-NNN
```
Долгий запуск — в фоне, без опроса. Итог Codex — `<worktree>/.codex-last.md`.

**Claude делает сам, только если:**
1. `check` вернул 2 (Codex не установлен/не залогинен) — сказать владельцу, что Codex не подключён;
2. `run` вернул 3 (закончились лимиты) — сказать владельцу и доделать самому;
3. Codex дважды не справился с одной задачей (после уточнения TASK) — сказать, что пошло не так;
4. владелец в этом сообщении прямо попросил «сделай сам»;
5. правка ≤ 10 строк в одном файле (опечатка, порог, строка перевода) — TASK дороже самой правки.

В отчёте владельцу всегда писать, кто сделал работу: «Codex реализовал, Claude проверил» или
«Сделал сам, потому что …» с причиной из списка выше.

**Codex обратно Claude не делегирует:** у Claude маленькие лимиты. Если Codex упёрся в вопрос
вкуса или смысла — пишет вопрос в «Заметки» задачи и заканчивает.

## Маршрутизация по типу задачи
| Тип задачи | Исполнитель | Ревьюер |
|---|---|---|
| Новый экран, анимации, UX-поток | Claude: спецификация + ключевые компоненты; Codex: рутина вокруг | Claude (дизайн + тексты) |
| Тексты, онбординг, пейволл, пуши | Claude | — |
| Разбор отзывов (triage) | Claude (Sonnet, коротко) | владелец в Telegram |
| Баг с понятной причиной, рефакторинг, тесты | Codex | Claude только если UI |
| Бэкенд Yandex Cloud (функции, YDB), CI | Codex | Codex (self-review) |
| Нативный модуль `pikkalo-vision`, алгоритмы фото | Codex реализует, Claude ставит задачу и проверяет логику | Claude |
| Миграции зависимостей, массовые правки | Codex | — |
| Непонятный баг, нужна диагностика | Codex (дешевле перебор) → если не нашёл, Claude | — |

Колонка «Исполнитель» — при подключённом Codex. Если Codex недоступен, всё делает Claude (см. выше).

## Экономия токенов
1. **Одна правда в файлах, а не в чате.** Решения — в `docs/DECISIONS.md`, задачи — в
   `tasks/TASK-NNN.md`. Агенты читают файл, а не пересказывают историю.
2. **Короткие инструкции верхнего уровня.** `AGENTS.md` и `CLAUDE.md` ≤ 100 строк, детали —
   в справочниках скилла, которые читаются только по необходимости.
3. **Передача работы — через задачу-файл** (шаблон ниже): цель, файлы, критерии готовности.
   Исполнитель не исследует проект заново.
4. **Узкий контекст.** Указывай конкретные файлы и строки; не проси «посмотри весь проект».
5. **Дешёвая модель для простого.** Triage, переименования, тексты — Sonnet/Haiku
   (`--model sonnet`); Opus — только архитектура и сложный UI.
6. **Ревью диффа, а не репозитория.** Ревьюер получает `git diff main...HEAD`, а не дерево.
7. **Не дублировать работу.** Один исполнитель на задачу; второй агент — только ревью.
8. **Кэшируемые префиксы.** Стабильные инструкции в начале промптов, изменяемое — в конце.
9. **Новая сессия на новую задачу.** Длинные сессии дороже: каждое сообщение тянет историю.
10. **Короткие ответы.** Итог первой строкой, без воды и повторов — [communication.md](communication.md).

## Шаблон задачи `tasks/TASK-NNN.md`
```markdown
# TASK-NNN: <коротко>
Исполнитель: codex | claude      Ревьюер: claude | —      Источник: issue #N | владелец
## Цель
<1–3 предложения: что должно стать правдой для пользователя>
## Контекст
- Файлы: src/…/Foo.tsx:40-120, src/…/bar.ts
- Решения: DECISIONS.md#… (если есть)
## Сделать
1. …
## Не делать
- …
## Готово, когда
- [ ] …
- [ ] тесты: `npm test -- foo`
- [ ] инварианты Pikkalo соблюдены (.agents/skills/pikkalo/SKILL.md)
```

## Локальный запуск Codex
- `codex exec --sandbox workspace-write -c sandbox_workspace_write.network_access=true "…"`
  из корня репозитория, на отдельной ветке; сеть нужна для npm.
- В этом режиме `.git` для Codex только для чтения — **коммиты делает Claude после ревью**.
  Codex пишет предлагаемые сообщения коммитов в «Заметки» задачи.
- Длинные задачи запускать в фоне, лог — во временную папку; не опрашивать.
- Параллельные задачи — каждая в своём `git worktree` (≈1,3 ГБ с `node_modules`, до 4 ГБ
  с Android-сборкой). **Удалять worktree сразу после вливания**, APK собирать в основной папке.
- После Codex демон Gradle держит блокировку `android/.gradle`: `./gradlew --stop`,
  при ошибке «Operation not permitted» — удалить `android/.gradle` (генерируется заново).
- Вливание через PR: `gh pr create` → проверки → `gh pr merge --merge --delete-branch`.
  Не `--rebase`: он переписывает хэши и расходится с локальным `main`.

## Грабли Android release (проверено на эмуляторе 25.11)
Тесты Jest/JVM их не ловят — **каждую задачу проверять release-сборкой на эмуляторе**:
- **R8 вырезает классы, которые ищутся рефлексией** → падение только в release. Нужны keep-правила
  через `expo-build-properties.android.extraProguardRules` (уже есть: WorkManager/Room, ML Kit).
  Новая нативная библиотека с рефлексией → добавить её правило.
- **Мост Expo не передаёт `null` внутри словарей** → нативный ответ «сжимать» (`compact`), а в JS
  восстанавливать `null` (`normalizeAnalysis` в `modules/pikkalo-vision/src/index.ts`).
- **Hermes без `Intl.RelativeTimeFormat` и `Intl.ListFormat`** → не использовать или делать запасной
  вариант (Jest на Node их имеет и не поймает).
- **Новый экран вне вкладок — в `Stack.Protected` в `app/_layout.tsx`**, иначе он доступен до онбординга
  и может открыться первым.
- **Решение «в корзину» из экрана группы — с `groupId`** (`useTrashFlow.request(assets, { groupId })`),
  и оставленные кадры — `keep`/`best` в журнал, иначе награды не засчитают группу.
- Проверка: `pm clear` + `pm grant … READ_MEDIA_IMAGES` даёт чистый запуск; ошибки JS — `adb logcat -b crash`;
  обфусцированный стек — `android/app/build/outputs/mapping/release/mapping.txt`.

## Процесс
1. Задача появилась (отзыв, идея владельца, баг) → маршрут по таблице.
2. Если задача на UI — Claude пишет спецификацию экрана (состояния, движение, тексты) в
   задачу-файл; Codex реализует по ней.
3. Исполнитель открывает PR с `Closes #N` и ссылкой на TASK.
4. Ревью по режиму `review` скилла → правки → владелец вливает.
5. Решения, принятые по ходу, — одна строка в `docs/DECISIONS.md` (дата, что, почему).
